# FND-19 — Chuẩn lập trình backend

- Trạng thái: Chuẩn đề xuất cho dự án
- Stack đã thống nhất: Spring Boot/Java, PostgreSQL
- Phạm vi: áp dụng cho platform và mọi module backend đang được triển khai.

## 1. Ranh giới module

- Tổ chức package theo module nghiệp vụ trước, lớp kỹ thuật sau. Ví dụ: `com.vinamik.erp.production.api`, `.application`, `.domain`, `.infrastructure`.
- `api` nhận HTTP, xác thực input và chuyển thành lệnh/query; `application` điều phối use case và transaction; `domain` giữ quy tắc nghiệp vụ; `infrastructure` chứa JPA, truy cập DB và tích hợp.
- Controller không chứa quy tắc nghiệp vụ; Entity/JPA không được trả thẳng thành JSON. Dùng request/response DTO để API không phụ thuộc cấu trúc lưu trữ.
- Module chỉ gọi public API/contract của module sở hữu dữ liệu. Không import entity, repository hoặc service nội bộ module khác; không tạo vòng phụ thuộc.
- Platform/common chỉ chứa năng lực dùng chung thật sự như xác thực, phân quyền, audit, xử lý lỗi và tiện ích kỹ thuật nhỏ; không biến thành nơi chứa nghiệp vụ.
- Sản xuất tham chiếu hồ sơ nhân viên qua hợp đồng Nhân sự và gửi yêu cầu nhập/xuất qua hợp đồng Kho. Chỉ Kho ghi sổ giao dịch và tính tồn thực tế.

## 2. API và lỗi

- Dùng REST API có version, thống nhất quy tắc đặt tên resource, phân trang, lọc và sắp xếp; giới hạn trường sort/filter để không cho phép query tùy ý.
- Kiểm tra dữ liệu ở cả ranh giới API (Bean Validation) và quy tắc domain. Không dựa vào giao diện để ngăn dữ liệu sai.
- Chuẩn hóa response lỗi: mã lỗi ổn định, thông báo hiển thị bằng tiếng Anh theo yêu cầu dự án, correlation ID và chi tiết validation an toàn. Không trả stack trace, SQL hoặc bí mật cho client.
- Dùng trạng thái HTTP nhất quán: 400 dữ liệu không hợp lệ, 401 chưa đăng nhập, 403 thiếu quyền, 404 không tồn tại/không được phép lộ, 409 xung đột trạng thái hoặc dữ liệu.
- API không được đổi ngôn ngữ thông báo tùy module. Success/error gửi client bằng tiếng Anh; log vận hành nội bộ bằng tiếng Việt.

## 3. Phân quyền và dữ liệu nhạy cảm

- Mặc định từ chối nếu chưa khai báo quyền (deny by default). Kiểm tra quyền ở backend cho từng query và command; ẩn/disable nút ở frontend chỉ là hỗ trợ UX.
- Tách quyền xem khỏi tạo/sửa/xóa/xác nhận/hủy/ghi sổ. Quyền phải được kiểm tra cả ở tầng API lẫn use case quan trọng, gồm kiểm tra phạm vi bản ghi nếu nghiệp vụ có giới hạn đơn vị/kho.
- Ghi audit cho thao tác quan trọng với người thực hiện, thời điểm, đối tượng, hành động và correlation ID; không ghi mật khẩu, token, dữ liệu định danh nhạy cảm hoặc toàn bộ request tùy tiện.
- Secret và cấu hình môi trường lấy từ biến môi trường/secret store. Không commit secret, không log thông tin kết nối.

## 4. PostgreSQL, giao dịch và nhất quán

- Mọi thay đổi schema đi qua migration Flyway có version; không dùng Hibernate `ddl-auto=update` làm cơ chế triển khai schema. Kiểm tra migration trên database mới và database có dữ liệu.
- Đặt transaction ở ranh giới use case, giữ giao dịch ngắn. Không giữ transaction mở trong khi chờ người dùng, gọi dịch vụ ngoài chậm hoặc xử lý file lớn.
- Tiền và số lượng không dùng `float`/`double`; dùng `BigDecimal` với precision/scale đã thống nhất. Ngày nghiệp vụ dùng `LocalDate`; thời điểm hệ thống lưu theo UTC (`Instant`) và chỉ chuyển múi giờ ở giao diện.
- Dùng ràng buộc DB cho bất biến dữ liệu có thể biểu đạt bằng constraint, khóa ngoại và unique index. Identifier CSDL, permission code và migration dùng tiếng Anh chữ thường snake_case; xem docs/database_design.md để dùng đúng schema, bảng sở hữu và quy tắc đặt khóa.
- Dùng bigint generated by default as identity cho khóa nội bộ, mã nghiệp vụ thành cột riêng có unique constraint; quantity dùng numeric(18,6), tiền dùng numeric(18,2), thời điểm dùng timestamptz và ngày nghiệp vụ dùng date, trừ khi task có yêu cầu đã xác nhận khác.
- Với ghi sổ kho hoặc command có thể bị gửi lại, bảo đảm tính lặp an toàn (idempotency), xử lý cạnh tranh bằng version/khóa thích hợp và kiểm thử không âm tồn nếu quy tắc nghiệp vụ không cho phép.
- Giao dịch kho đã ghi sổ không bị sửa/xóa âm thầm; điều chỉnh bằng nghiệp vụ đảo/điều chỉnh có dấu vết audit. Module khác không cập nhật trực tiếp số dư kho.
- Trước khi đổi hoặc xóa dữ liệu, cần migration có đường chuyển đổi/rollback phù hợp; không sửa dữ liệu production thủ công để làm cho kiểm thử qua.

## 5. Kiểm thử và vận hành

- Unit test cho quy tắc domain/use case; integration test cho API, phân quyền, migration và luồng xuyên module quan trọng.
- Kiểm thử truy cập PostgreSQL thật cho hành vi phụ thuộc đặc tính PostgreSQL; không chỉ dựa vào mock repository. Dùng môi trường kiểm thử sẵn có, không tự thêm hạ tầng bắt buộc ngoài phạm vi.
- Tối thiểu kiểm thử: xem được khi có quyền đọc; bị 401 khi chưa đăng nhập; bị 403 khi thiếu quyền ghi; cập nhật tồn qua Kho; gửi lại command không tạo giao dịch trùng.
- Log có ngữ cảnh bằng tiếng Việt, có module/use case/correlation ID và kết quả; bỏ thông tin xác thực, secret và payload nhạy cảm.
- Trước khi bàn giao chạy format/lint nếu dự án đã cấu hình, test liên quan và build toàn backend; báo rõ phần nào chưa chạy được.

## 6. Không làm

- Không truy cập bảng/entity/repository của module khác để tiết kiệm một lần gọi contract.
- Không trả JPA entity, không bỏ qua backend authorization, không nuốt exception, không trả lỗi chung khiến không điều tra được.
- Không dùng migration phá hủy dữ liệu hoặc thay đổi schema trực tiếp ngoài quy trình version hóa.
- Không mở rộng nghiệp vụ ngoài task/nguồn môn học đã chốt nếu chưa có quyết định mới.

## 7. Repository và SQL an toàn

- Service/application không giữ `EntityManager` hoặc tự ghép câu SQL; mọi truy vấn nằm trong repository của chính module.
- Dùng Spring Data JPA/JPQL cho CRUD, join và phân trang khi phù hợp; có thể dùng projection để chỉ tải các cột cần thiết. Trường hợp bắt buộc dùng tính năng PostgreSQL như khóa dòng, ghi sổ ledger hoặc `ON CONFLICT`, repository được phép dùng native query qua Spring Data JPA hoặc `EntityManager`.
- Không dùng `JdbcTemplate`, Spring JDBC hoặc API JDBC trực tiếp trong code ứng dụng. PostgreSQL JDBC driver vẫn cần ở tầng kết nối nội bộ của Hibernate/JPA; điều này không cho phép module tự gọi JDBC.
- Mọi giá trị đến từ request phải đi qua bind parameter (`?`, named parameter hoặc tham số của `@Query`). Không nối chuỗi giá trị tìm kiếm, mã chứng từ, sort field hoặc quyền người dùng vào SQL.
- Dynamic sort/filter chỉ được chọn từ allow-list cố định; không truyền tên cột tùy ý từ client.
- Repository không thay thế kiểm tra quyền: controller/use case vẫn phải kiểm tra authentication, permission và phạm vi bản ghi trước khi gọi repository.
